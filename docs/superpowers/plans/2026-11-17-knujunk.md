# KnuJunk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Addon de WoW Forever que marca en las bolsas (21 addons de bolsas + Blizzard + genérico) y en la ventana de botín qué se puede vender (monedita) y qué material sirve a una profesión (martillito verde = tuya, gris = no tuya), con el motivo en el tooltip.

**Architecture:** Un clasificador puro (`Classify`) decide la marca de un item a partir de tablas generadas desde wago.tools (`wowf`) y de un contexto del personaje (clase, profesiones, misiones). Un módulo de marcas dibuja la textura sobre cualquier botón; cada addon de bolsas tiene un adaptador chico que sólo traduce «este botón muestra bolsa X, slot Y» a `Marks.Update`. QuestieDB se usa si está cargado, nunca embebido.

**Tech Stack:** Lua 5.1 (cliente Forever, Interface 16001), LuaJIT para pruebas (`C:\Users\KnuPwns\AppData\Local\Programs\LuaJIT\bin\luajit`), Python 3 para el generador de datos, KnuLib-1.0 MINOR 4 embebida, BigWigsMods/packager.

**Spec:** `docs/superpowers/specs/2026-11-17-knujunk-design.md`. Respaldo: `E:\Repositorios\Personal\_datos\WOWAddons\knubags\` (`analisis/_sintesis-gemini.md` §4 mecanismo de cada bolsa, con correcciones en `analisis/_auditoria-codex.md`; código de referencia de la competencia en `competencia/<slug>/src`, **sólo para leer, nunca copiar**).

## Review Focus

1. **Item sin datos cargados** (`GetItemInfo` devuelve nil la primera vez): sin marca, y se re-marca cuando llega `GET_ITEM_INFO_RECEIVED`. Prueba en Task 3 y Task 6.
2. **Botón reciclado** (la bolsa reusa el botón para otro item o lo deja vacío): la marca anterior desaparece. Prueba en Task 6.
3. **Item útil por un motivo y tirable por otro** (gris que es objetivo de una misión activa, equipo inútil que inicia misión pendiente): gana «útil», sin monedita. Prueba en Task 3.
4. **Override del jugador** (`keep`/`sell`) gana sobre cualquier regla y sobrevive a `/reload`. Prueba en Task 3 y Task 12.
5. **Ráfaga de `BAG_UPDATE_DELAYED`** al lootear o ordenar: un solo recálculo por ráfaga, no uno por evento. Prueba en Task 6.

Orden de decisión (fijo):

5. Cualquier `nil` de `isQuestDone` (no se sabe) → sin monedita.
